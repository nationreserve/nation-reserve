# Public content governance

Public content is currently version-controlled with code review. Financial, legal, security, API, availability, and medical claims require an authorized reviewer before publication. A future CMS must retain author, reviewer, timestamp, previous content, new content, publication state, scheduling, and rollback history.

The following remain publication blockers rather than placeholders presented as fact: legal entity/address, approved legal agreements, Republic destination and app-store URLs, public support/security/privacy addresses, status feed, live statistics, contact delivery, production canonical origin, and social-preview artwork.

Prohibited claims include guaranteed income, utilization, queue dates, capacity, robot performance, universal compatibility or legality, risk-free ownership, schedule-based pay, heartbeat as proof of work quality, and approval before verification.
