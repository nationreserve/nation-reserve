# Privacy Review

## Classifications

| Class | Examples | Access rule |
|---|---|---|
| Public | Published product and policy content | Anonymous read |
| Account | Email, display name, session/device metadata | User and narrowly authorized support |
| Organization confidential | Facilities, work orders, contracts, exact locations | Active scoped members and explicit counterpart grants |
| Restricted training | Motion recordings, task assets, calibration files | Explicit versioned grants; revocation blocks future access |
| Restricted operational | Robot serials, heartbeat evidence, incidents | Assignment participants, manufacturer operations and authorized platform roles |
| Restricted financial | Invoices, payment evidence, owner statements and payouts | Correct organization finance roles and separated platform billing roles |
| Security sensitive | Credentials, hashes, signatures, audit evidence | Security/operations systems; never exposed in notifications or timeline text |

Privacy boundaries require minimum collection, organization scope, separate manufacturer threads, hidden recipient lists, grant-controlled training/location data, redacted timelines, non-leaking search and notification bodies, read-only support by default, export filtering and documented retention. Database-backed negative tests, notification review, object-store policy review and legal retention approval remain pending.
